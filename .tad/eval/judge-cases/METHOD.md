# METHOD — 测量层方法正本（judge-cases 回放与对照类记录）

本文件是 EPIC-20261027-r4-batch Phase 2 测量层一包的方法正本：只管本包各面
（考题集回放、Phase 3 代码指标对照），不回溯改造其它评测资产。
建集规则本体在同目录 `INDEX.md`；本文件管「样本怎么生产、判读怎么预声明、结果怎么分层报」。

## 1. 样本生产线（五步）

1. **关闭案件**：只取已关闭、落盘、带结论的案件（verdict／处置／日志件在盘可指）。
   未关闭、无结论、仅被提及的，不入集。
2. **抽冻结输入**：把判者当时看到的产物真冻结进集内——快照正文或 fixture 本体落
   judge-cases 目录（案卷内嵌或同目录附件），附源路径＋内容 sha256。只有活路径、
   无快照者不算抽毕，不得入集。
3. **以 finding 形态写期望**：期望抓获写成 location＋scenario 两件（照 review-contract
   §2 的 finding 形态）；写不出可判形态的期望，该案退回、不入集。
4. **定 class 与 metric_candidate**：class 取 INDEX.md 受控表的短名（新 class 先入表
   再用）；`metric_candidate: yes|no` 标该败例是否属代码机械类、可供 Phase 3
   指标面对照。
5. **入 INDEX**：在 INDEX.md 登记案号、来源指针、class 与版本行计数；干净对照按
   INDEX 的取材规则另行登记为 control 条目。

## 2. 判据预声明（回放／对照类记录开跑前冻结）

凡回放或对照类记录，开跑前必须把判读规则写进该记录的头部并标 `frozen`。
冻结范围含三件，缺一不算冻结：

- **判读规则**：逐案如何判 caught／missed／false-alarm／n/a 的字面规则；
- **案例输入哈希集**：本轮所用全部案例冻结输入的 sha256 集合；
- **被测目标版本标识**：被测变更（判据／评审提示／模型锁）的前／后版本快照指针
  或内容 sha256；草案类目标以草案所在文件的 sha256 为版本标识。

见过结果之后再改三件中任一，该轮作废重跑，或在记录头部明标 `exploratory`
（exploratory 轮只记观察，不计入回放记法的 caught／false-alarm 汇总）。
先例：借 4 试验的判据于 Gate 2 PASS 时冻结、机械套用
（`.tad/evidence/self-review-r3-20261006/g2-borrow4-trial/build-record.md`）。

## 3. 断言分层（A／B 两层分开计数）

回放与对照记录的汇总分两层报，禁止混成单一分数：

- **A 层 — 机械断言**：计数、在盘、exit code、字符串相等、哈希一致这类可复算断言。
- **B 层 — 量规判断**：finding 形态是否命中（location＋scenario 是否对上期望）这类
  需判读者判读的断言。回放的逐案 caught／missed／false-alarm 属 B 层。

汇总形态：A 层逐项列结果；B 层只报 `caught n/N`、`false-alarm m/M` 并附案号清单
（N＝本轮败例总数，M＝本轮干净对照总数，来源为 INDEX 登记的 control 条目）。
不许折算成百分比，不许排名。

## 4. 附注：Context Rot 两轴（观察框，不建指标）

读回放结果时带两个观察轴，仅作解释框架，不设交付件、不建指标：

- **单链内上下文增长**：同一链越往后，判者上下文越长，早期判据与约束的实际
  权重可能被稀释——同一判者在长链后段的 missed 与在短链中的 missed 不宜直接同读。
- **指令遵循静默衰减**：长上下文中指令遵循会静默变弱而不报错——回放若发现
  「规则在盘、判者未用」，先按本轴记观察，再议是否属判据文本问题。

两轴只影响读法，不改变第 2、3 节的冻结与计数口径。
