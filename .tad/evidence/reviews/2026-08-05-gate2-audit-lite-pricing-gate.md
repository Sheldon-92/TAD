## 决定性转折：拆单（R2 → R3）

R1+R2 共 13 个 P0，**11 条长在存量审计的机械核验层**（载体核验 / 状态词汇 / 反证搜索）。

**根因**：「Blake 有没有认真找过载体」**不是可 grep 的东西**。两名 reviewer 各自独立演示了绕过：
- 选一个刻意生僻的关键词跑空结果，即可"合法"证明无载体
- 搜索目录写死 `.tad/evidence/ .tad/logs/` 会漏掉 `.tad/archive/handoffs/` 下**路由机器自己的原始设计文档**
  ——即"认真做也会踩的坑"，比偷懒的坑更严重
- 叠加"砍除名单非空"断言缺失后，**最省事的完全合规输出是全标 PROVISIONAL：9 条 AC 全绿，
  而砍除名单为空**——该 phase 存在的唯一理由产不出来（激励反转）

**处置**：整个存量审计移出 → Epic P1b，验收改为 **fresh reviewer 对高风险行独立抽查**。
撞在既有原则 `AI/Human Judgment Domain Awareness`：验证域交 grep，判断域交独立视角。

## 可复用教训（候选蒸馏）

1. **同一缺陷家族会连跳**：AC4/AC5 的「无可运行命令 → 空输入即假 PASS → 未绑定变量恒 FAIL」
   三跳。修一类缺陷必须横向扫同一批新写的兄弟。
2. **围栏要双向自测**：只测"拦得住违规"（负向）会漏掉"放得过合法交付"（正向）。
   R3 的两个 P0 正是这么漏的。**positive control 与 negative control 同等必要。**
3. **判断域 vs 验证域**：可机械验证的交 AC，需要判断的交独立 reviewer。
   把判断塞进 grep，会持续长新洞——补一个长一个。
4. **本机 `/usr/bin/awk` 无法比较中文字符串**：含 >127 字节的串被当作数值 0，
   `awk 'BEGIN{print ("身份"=="精髓")}'` → **1**。`-v` / `ENVIRON` / 字面量 / `(x "")` 全部受影响。
   本仓库满是中文，任何用 awk 做字符串相等的校验脚本会对**任何输入**报 PASS。
   → 应进 `patterns/shell-portability.md`。
5. **协议文本 + 无机械留痕 = 事后不可验证**：本轮出现三次（准入登记、反证搜索、到期扫描）。
   凡是"必须做 X"的协议条款，都要问一句"事后怎么区分做了和没做"。
6. **验证装置可能比被验证物还重**：本单交付 ~30 行文本，Gate 2 耗约 928K tokens，
   而 reviewer 抓的几乎全是**验证装置自身**的缺陷，不是交付物的。
