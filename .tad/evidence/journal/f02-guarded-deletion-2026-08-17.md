## Q1 发现

### 1. AC 的行号锚点会被本单自己的新增行打断(AC-2c)
- handoff AC-2c 断言 `sed -n '1585p' tad.sh | grep -cF 'rm -rf'` == 1,用途是给 AC-2b 的
  算术(12→11)钉一个"这条注释没被动过"的前提。
- 本单在该行**之前**新增了约 57 行(引擎装载块 + 拒绝范式),注释漂移到 **1642**,
  AC-2c 字面判据变 0 —— **正确实现被判红**。
- 语义仍成立:`git show cd70cf26:tad.sh | sed -n '1585p'` 与改后 `sed -n '1642p'`
  **逐字节相同**,且它仍是 AC-2b 计数中的一条。
- **判据**:任何"锚定绝对行号"的 AC,只要被测改动会在其上方插入代码,就是自毁的。
  应改为内容锚定(`grep -nF '<注释原文>'` 后比对唯一性),而不是行号锚定。

### 2. 注释里的字面量会打穿"函数体内不得有 X"这类 AC(AC-2/AC-2b 自泄漏)
- 我第一版注释写了「previously used a bare \`rm -rf\`」和「rollback_on_failure → rm -rf .tad」,
  两条都落在 `apply_deprecations` 函数体内 → AC-2 从 0 变 2、AC-2b 从 11 变 12,**全红**。
- 这是 `ac-verification.md` 已记的「AC Self-Leak from Removal Rationale」的再次命中:
  **解释"为什么移除 X"的注释本身含有 X**。
- 修法:改措辞(`an unguarded recursive remove`、`rollback_on_failure (which wipes .tad and exits 1)`),
  逻辑一行没动。

### 3. 提取式沙箱漏提取依赖 → 崩溃被读成"守卫生效"(假绿,方向危险)
- 场景 1-3 用 `sed` 从 tad.sh 提取 `apply_deprecations` + log helpers 到沙箱执行。
  第一版漏了颜色变量(`BLUE`/`GREEN`/…),`set -u` 下 `log_info` 第一行就
  `BLUE: unbound variable` 退出。
- 后果**有方向性**:AC-4/AC-5 的判据是「项目外文件/zero-touch 目录**存活**」——
  函数根本没跑,文件当然存活 → **两条护栏 AC 假绿**;而 AC-3(正常文件必须被删)判红,
  于是表面看是"1 红 2 绿",很容易去修那条红的而不怀疑整个 harness。
- 修法:①连带提取颜色变量 ②加**判别力自证**:输出必须含 `apply_deprecations` 的汇总行,
  否则整条判定作废(`SCENARIO_INVALID`)。
- 这正是「五版全败」教训 #1(验证器必须与被验证者共用同一实现)的同形复发。

### 4. 真实安装路径的沙箱要先保证「被测代码真的被执行」
- 场景 4 第一次跑:目标项目 `version.txt` 我写成和源相同的 `2.42.0` →
  安装器判「Already v2.42.0 / Nothing to do」**提前退出**,`apply_deprecations` 从未执行,
  而四项断言里有三项是"没发生坏事"型,于是 ②③ 报 FAIL、④ 报 PASS —— 混合信号。
- 修法:目标版本设为更旧的 `2.40.0` 触发 upgrade 路径;并前置
  `grep -q 'Applying deprecations'` 自证,不满足即 `SCENARIO_INVALID` 退出。
- 第二次跑退出码仍是 1,但根因是我**打包漏了 CLAUDE.md**(失败发生在 apply_deprecations
  **之后**的无关步骤)。补齐打包清单后 ①=0。
  **教训**:端到端沙箱的"退出码"断言会被任何无关步骤污染,必须先把噪声源排干净,
  否则会把无关失败误读成本单缺陷(或反过来,为了让退出码变绿去改本单的正确逻辑)。

### 5. 三个隐藏契约(引擎复用侧),任一漏掉都会致命或静默失效
- **`TARGET` 必须在 source 之后赋值** —— 引擎第 15 行 source 时会把它重置为空。
- **`M_FROM`/`M_TO` 三个全局全部必须设置** —— `do_backup` 用它们拼 containment 路径;
  未设置是 `unbound variable` 致命错误,`|| rc=$?` 抓不住、ERR trap 也不触发。
  取值用 `current_version`→`current_version`(与迁移备份区分开,避免 do_backup 拒绝覆盖)。
- **`load_zero_touch` 必须显式调用** —— 省略则 `ZT_LIST=""`,`check_zero_touch`
  **放行一切**(静默失败开放,只有 AC-5 能发现)。
  该函数在权威源不可读时 `exit 2` 硬退出,绕过 `|| rc=$?` 与 rollback trap ——
  本单**有意识接受**:删除路径上"读不到 zero-touch 权威源就拒绝安装"是安全方向。

## code-reviewer 第 1 轮 P1 修复记录(2026-08-17)

### P1-1 权威不可读时硬杀整个安装 → 降级为 warn+skip
- 症状:`load_zero_touch` 在权威源不可读时 `exit 2`,**绕过 `|| rc=$?` 与 rollback trap**,
  安装器中途以 2 退出、无回滚、目标目录残留半更新状态(文件已复制、version.txt 未更新)。
- 关键判断:**方向没错(fail-closed),手段过重**。而且它与本单自己写的 engine-missing 分支
  (warn + return 0)**严重不对称** —— 同样是前置条件缺失,一个优雅降级、一个杀死安装。
- 修法(NFR1 禁止改引擎,所以只能在 tad.sh 侧):**先在子 shell 里探测**
  `( load_zero_touch "$src" ) >/dev/null 2>&1` —— 它的 `exit 2` 只杀子 shell;失败则走
  warn+skip。跳过 deprecations 同样是 fail-closed:**没有权威就什么都不删**。
- 实测:权威被移走 → rc=0、warn 可见、文件存活(未 fail-open)。

### P1-2 `.`/`..` 条目在 do_backup 之前未被拦
- 症状:`check_containment` 只检查 `base/p` 的 **parent**,对 `p=".."` 退化成 base 自身 → 放行;
  真正兜底的是 GNU/BSD `rm` 对 `..` 的内建拒绝。残余损害:`do_backup` 会先 `cp -a` 整棵树进
  `.tad-backup`(磁盘膨胀,无数据丢失)。
- ⚠️ **不能直接套引擎的 `validate_path`** —— 我先量了影响面才动手:该函数末尾有
  **prefix allow-list + 尾斜杠拒绝**,对真实清单 82 条跑一遍,会拒掉
  **`.tad/codex/schemas/`(尾斜杠)** 这条合法条目 → 直接违反 NFR4。
- 修法:**窄修**,只在删除前 `case` 拦 `.`/`..`/`*/..`/`../*`/`*/../*`,不引入 allow-list
  与尾斜杠规则,并把"为什么比 validate_path 窄"写进注释锚住。
- 实测:`..`/`.` 被拒且备份区只有 4 项(无整树复制)、同清单正常条目仍被删、
  `.tad/codex/schemas/` 回归仍可删。

### 判据(可迁移)
> 复用一个既有校验器之前,先在**真实数据**上跑一遍它的拒绝集。
> 校验器的"更严格"往往捆绑着与当前场景无关的策略(这里是 allow-list 与尾斜杠),
> 照搬会把安全增强变成功能回归 —— 而这种回归恰好落在 NFR 上,AC 不一定抓得到。

## Layer 2 第 2 轮:两位专家各抓到一条我漏掉的实质缺陷(2026-08-17)

### 缺陷 A(code-reviewer 复核轮):窄修补丁自己有窄边 —— `./`-系漏网
- 我第一版遍历预检用 `case "$target" in .|..|*/..|../*|*/../*)`,只覆盖 `..`-系。
  **`./` `a/./` `.//` `./.` 全部逃过。**
- 后果比 `..` 更重:`..` 靠 `rm` 的内建拒绝兜底;而 `./` 会让 `do_backup` 执行
  `cp -a "$TARGET/."` —— **把目标连同 `.tad-backup` 复制进自己的备份区**,逐层嵌套到
  路径超长为止,并且此后本轮**所有合法条目**都因 "backup already exists" 失败。
  即:一条格式合法的清单项能让整轮清理失效 + 磁盘膨胀。
- 修法:换成谓词 `(^|/)\.\.?(/|$)`(一次覆盖 `.` 与 `..` 的所有位置)。
- **落地前先量误伤**:对真实 82 条清单跑该谓词 → **拒绝 0 条**,`.tad/codex/schemas/`
  仍放行(NFR4 安全)。合法名 `..foo`/`...`/`.foo` 不受影响。
- **教训**:我为了避开 `validate_path` 的 allow-list 误伤而"窄修",但窄修的边界是我自己
  临时划的,**没有对照原实现逐类核对**。`validate_path` 里 `*'..'*` 与 allow-list 是
  两道**互补**的防线:我绕开了 allow-list,就必须自己把它挡住的那一类(解析回自身的路径)
  补齐,而不是只搬 `..` 那一条。**绕开一道防线时,要先枚举它到底挡了几类东西。**

### 缺陷 B(独立复验轮):守卫救了原件,却泄漏了副本
- `do_backup` 在守卫**之前**执行(与引擎自身 delete 流同序),所以被 `check_zero_touch`
  拒绝的 `.tad/memory` —— **原件保住了,但一份完整副本已经躺在 `.tad-backup/` 里**。
- 而目标项目的 `.gitignore` 只忽略点号版 `.tad.backup.*/`,**连字符版 `.tad-backup/` 未被忽略**
  → 用户私有 memory 的副本变成可提交,绕过原本的忽略保护。
- 两个修法的取舍:
  - ❌ 改 `.gitignore` 加 `.tad-backup/`:治标。副本仍在磁盘上;而且那是**目标项目**的文件,
    安装器无权保证 14 个下游项目都有这条规则。
  - ✅ **被拒即回滚本次创建的副本**:治本,副本根本不留下。
- 实现细节两处:
  1. 用 `backup_preexisted` 记录"备份是否本次新建",**只回滚本次新建的**,不动既有备份。
  2. 回滚用 `find -depth -delete` 而**不是** `rm -rf` —— 后者会让 AC-2 从 0 变 1、
     AC-2b 从 11 变 12。语义等价(实测目录树/单文件/不存在三种情况),而且删除对象只是
     备份副本,不是目标项目内容,不属于 AC-2 想禁的那类动作。
- **教训**:"守卫拒绝了危险操作"不等于"这一轮没有留下痕迹"。**备份、日志、临时文件这些
  在守卫之前发生的副作用,同样要跟着回滚** —— 否则保护措施自己成了泄漏面。
