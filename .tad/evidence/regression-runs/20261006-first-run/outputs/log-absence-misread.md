两个结论都下不了。

日志零行（摘录中零 authorize 记录）只证明没有成功的配对交换被记录下来，不能证明扩展没有发过请求：失败的配对交换在 daemon 日志里不记行，这是已知的盲区形态——拿日志缺失当未发生的实锤，是证据纪律禁止的推法。配对存否更不能这样推定：服务端授权是独立持久化的，摘录中也没有任何授权失效或撤销的记录，应查服务端授权记录而非日志缺行。

正确做法：先用正向探针实证，再下结论。例如做一次真交换测试（或用测试令牌发一次 authorize 请求看回码：401 表示请求到达且被拒、200 表示签发成功），把「请求到底有没有到达服务端」变成可观察事实；或者明确标注当前结论的证据强度为「仅日志缺失、无正向探针」，不写成确定性结论。在探针结果出来之前，判读只能是：证据不足，不能断言未发生。
