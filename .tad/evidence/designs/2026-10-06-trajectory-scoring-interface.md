# 轨迹→评分接口前置口 — 接口设计（Epic P2 件 2.5，C6 只取前置口）

本件只出接口与判据定义，不落评分器实现。设计输入：MQ-6 判断正本 §B2/C6（`.tad/evidence/pm/2026-10-06-tad-sweep-proposal-judgment.md`）。字段名与件 2.7（`.tad/evidence/designs/2026-10-06-c2-failure-clustering-interface.md`）共用一套，不另立名。

## 1. 样本汇集面

来源枚举（样本只许出自这两面，不收散件）：
- 件 2.1 复跑记录：`.tad/evidence/regression-runs/<运行目录>/` 下的 scores 与 outputs；
- 各链 Gate 证据中的轨迹件：COMPLETION、Gate 评审件与链证据目录中可定位到步的记录。

单样本字段集（缺必填者只许登记为不可评分并注明缺项）：`step_id`、任务指针（票/HANDOFF 路径）、输入指针、轨迹（工具调用序列或其落盘指针）、结果、执行通道/模型、成本/耗时。其中成本/耗时可缺，缺失时在样本上标注，不阻断入集。

## 2. 标签定义

标签集三类，逐类给定义与示例：

- (a) **gate-verdict**：该样本所属步经历的 Gate 结论（门、结论、出具者）。仅作元数据字段，**不得作奖励标签**（理由见第 6 节约束）。示例：`gate-verdict: {gate: 3, verdict: PASS, by: code-review}`。
- (b) **failure-class**：失败归因标签，值域预留给件 2.7 的失败分类表（FC-1–FC-4），本文只占位引用、不自定值域。示例：`failure-class: FC-2`（执行缺陷，值域以件 2.7 文档为准）。
- (c) **human-spot-check**：人工抽查结论，三值写死：合格／误奖／不可判。示例：`human-spot-check: 误奖`（样本被判合格但抽查认为实为失败）。

## 3. 去标识化规则

样本入集前逐类剥离：
- 凭据与令牌：一切形态（密钥、token、会话标识、带凭据的 URL）；
- 含用户名的绝对路径（家目录前缀等可定位到个人的路径段）；
- 席位/项目专名在样本正文中的出现：以角色代号替换（如 PM/Alex/Blake/Reviewer）；
- 原始对话中的个人标识（姓名、联系方式、账号）。

入集前自查 grep 口径（模式类枚举，照行执行）：对样本正文跑密钥形态（`(?i)(api[_-]?key|token|secret|password)\s*[:=]`）、家目录路径（`/home/<name>/`、`/Users/<name>/`）、邮箱与手机号形态三组模式扫描；任一命中未处置 → 该样本不许入集。

## 4. 人工抽查与误奖处置

- 抽查率写死：按批入集样本计，人工抽查 **≥10%**；抽法以 step_id 哈希取模均匀抽样（可复现，不许人工挑选）。
- 误奖率 ＝ 抽查中判「误奖」数 / 抽查数。
- 误奖率 **>5%** 的批次**整批隔离**（quarantine）：隔离批样本不得用于任何调参/训练用途；隔离事实记入该批次记录（批次指针、抽查数、误奖数、处置人）。

## 5. 保留集

- 保留集比例写死 **≥20%**。划分规则：以 step_id 哈希取模，`hash(step_id) mod 5 == 0` 的样本入保留集。
- 保留集样本**不参与调参**，只作最终评测面。
- 划分在样本入集时即打标，事后不许重划。

## 6. 约束明文

**Gate PASS 不得直接当奖励信号。** Gate 结论是门槛判读（过/不过），不是质量标量；以 PASS/FAIL 直接构造奖励会把被测系统推向迎合门面而非做好任务（Goodhart）。奖励或评分信号必须来自独立于 Gate 的标注（本接口第 2 节标签集），且须经第 4 节抽查与误奖处置。

未来任何引用本接口的设计须逐字带此节。

## 7. 非目标

- 不做训练、不做调参、不选工具（C7 的许可证与数据出站未核，另议）。
- 本文不构成对任何训练框架的引入许可。
- 评分不触发自动奖惩、不改模型/通道路由、不作跨项目排名（接口层禁令，随本接口一并冻结）。
