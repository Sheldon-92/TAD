> Step 2 产物。封存后供 §6.3 独立复核 diff。行序即 ID（§1.5）。
> 输入：形态 B 每段三行（`防住过什么` / `删掉会怎样` / `删之前先找什么反例`）；失败类从「删掉会怎样」提取。

## 0. 连边原则（本文件自述）

1. 形态 B **明确互引**（一条的三行提到另一条防的失败类/名称）→ 连边（同根或互补）。
2. 「删之前先找什么反例」揭示的**替代关系**，替代不成立 → 互补；替代成立 → 冗余（需过 §4.5 #5 反证前置）。
3. 失败类属**同一防线主题**且删一条该主题出现实质缺口 → 互补。
4. 其余 → 独立（并逐行举证，§4.5 #4）。

## 4. 边界说明（诚实记录）

- D05（门禁）/D13（AC可执行）/D15（Ralph Loop）三者为「机械验证」三个独立机制，失败类不同（形式缺陷 / AC不可验证 / 实现错误）但形态 B **无互相引用**，且各自独立充分（Path Layering 语义下的三条独立防线），故**互相不连边**、判独立（D05、D15 分别与 D04 互补，D13 独立）。
- D13「删之前反例」写「事后审查能捕获 AC 不可验证」，「事后审查」指代模糊（可能指 D04/D05/D08），故 D13 不据此连边。
- D04 与 D05/D08/D14/D15 的互补均以「人审查 vs 机械验证 / 反跳过 / 同模型盲区」的不同失败类为依据；D04 未与 D13 连边（见上）。
