判据：§4.3 有序规则第 3 条——B1 为 `established` 且 B2 为 `established`；退路 B（指路文件）亦已成立（B4 `established`）。适用范围：无头面、逐 skill 符号链接；跨机同步副本未测。
**AGENTS.md 加载条件**（仅无头 `-p`、嵌套子会话下实测；交互面未测）: 该目录（工作目录）无 `CLAUDE.md` 时直接加载（A1、A4）；有 `CLAUDE.md` 且不含 `@AGENTS.md` 时被压住（A2）；`CLAUDE.md` 含一行 `@AGENTS.md` 时作为 include 带入（A3）。用户级 `~/.claude/CLAUDE.md` 不压住 `AGENTS.md`：A1、A4 是在该文件存在的机器上测的（A5 记录其存在），结果仍是 `AGENTS.md` 被加载。上级目录链上的 `AGENTS.md`/`CLAUDE.md`、`.claude/CLAUDE.md` 形态对结果的影响未单独测（unmeasured）。
**残项**: R-CC-1 无头面工具名册不含 `AskUserQuestion`，提问捕获无落点（D4；交互面未测）；R-CC-2 `InstructionsLoaded` 事件不报告内建模块加载的 `AGENTS.md`，仅 debug 日志可见，无 hook 级信号（A1）；R-CC-3 `post-write-sync.sh` 对 TAD 受管路径有副作用，按字面探针（新建非受管文件）只能得 partial（D2）；该结论只测了 Write 工具与两条路径（一条非受管的 `probe-d2.txt`、一条受管的 `.tad/active/handoffs/COMPLETION-*.md`），Edit 工具与其余受管路径未测；R-CC-4 登录态失效信号、超时形态、沙箱形态未测（②④⑤）；R-CC-5 交互面、跨机同步副本中符号链接的存活、上级目录链指令文件的影响未测（B2、A1）。

**R-CC-6**: 会话在项目的子目录启动时，上级目录的 `.claude/settings.json` 不被加载，项目 hook 一个都不触发（Alex 2026-10-08 在装置 `~/tad-cc-p2-hookcwd-20261008` 上各 1 次；Phase 2 冒烟在装好的项目子目录再测 1 次，同结果，见 `.tad/evidence/spikes/2026-10-claude-code-install-smoke/subdir-note.txt`）；同一次子目录会话里项目 skill 仍被发现（名册 102 项，与项目根一致）。会话在项目根启动时，项目 hook 以项目根为工作目录，`bash .tad/hooks/x.sh` 与 `bash "$CLAUDE_PROJECT_DIR/.tad/hooks/x.sh"` 两种写法都能解析；但会话里 `cd` 之后，相对写法的 hook 在子目录执行并 2/2 次跑到子目录里的另一份脚本（`phase4-hook-cwd-probe.md`），所以模板自 3.3.0 起锚定：`test -n "$CLAUDE_PROJECT_DIR" && { cd -- "$CLAUDE_PROJECT_DIR" \|\| exit 1; } && bash .tad/hooks/<脚本>`（变量为空或未设置时命令退出码 1、不运行脚本；目录不存在时 `cd` 打印 `cd:` 错误并以退出码 1 结束、不运行脚本；该命令串在 sh、bash、zsh、dash 下实测，Claude Code 内的工作目录探针只覆盖 SessionStart 与 PostToolUse；R-CC-6 仍在；脚本不存在时 hook 的表现未测）。

**R-CC-7**: 顶层按保存名调用 `Workflow({name})` 与 `/workflows` 列表可见性未提供（未测）；会话在项目子目录启动时相对 `scriptPath` 的解析未测。协议因此规定：会话工作目录不是项目根时不启动 workflow，先切换到 `git rev-parse --show-toplevel` 的输出（或请用户在项目根重开会话）再按相对路径调用——脚本内部的证据、模板与 args 路径都以项目根为基准；子目录会话里「证据会落在会话目录下」是推断，未实测。子代理不能调用 Workflow 工具：来自早先的项目观察，Phase 3 未重新实测。`spec-compliance-reviewer` 在 Phase 4 投影前不是已注册的子代理类型：此时派生通用子代理，并把 `.tad/agents/claude/spec-compliance-reviewer.md` 的正文作为其任务说明。派生子代理的真实运行见 `.tad/evidence/yolo/multi-harness-restore-and-cleanup/phase3-gate-report.md`。

**R-CC-8**: 迁移引擎拒绝路径中含符号链接的清单条目（`.tad/hooks/lib/migration-engine.sh` 的 `check_containment` 逐段检查，含最后一段），而 `--platform claude-code` 之后 `.claude/skills/<名>` 是指向 `.agents/skills/<名>` 的符号链接；所以今后的迁移清单不得再列 `.claude/skills/**` 路径，否则该版本步骤的其余删除会被整体拒绝（退出码 2，仅告警）。旧版镜像目录的清理改由安装器的旧安装接管负责（Phase 4a，`.tad/provenance/claude-legacy.tsv`）。来源：Phase 4 grounding 第 17 节。
