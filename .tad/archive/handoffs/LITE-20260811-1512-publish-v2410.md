- **D1｜publish-only**：走 release-runbook 七阶段的 1-4 + 7，跳过 5/6。
- **D2｜版本 2.41.0（minor）**：用户 2026-08-11 裁定。风险与缓解见 F5 + AC7。
- **D3｜两个提交集合，条数由 agent 定（rev5 更正）**：**closeout 集合** = 上一单 closeout（第 22-24 项）；
  **release 集合** = 版本 bump + CHANGELOG + Epic 全部改动 + preflight 基线 + verify.sh（第 1-21 项）。
  两集合路径互不相交。**tag 指向记录的 tip**（即 release 集合的最后一个 commit），不再钉死某个具体 SHA。
  A 组闸门失败时，修正以**追加 commit** 落在 release 集合内即可，无需 amend、也不违反 append-only。
  tip **之后**产生的证据（第 25 项）保持未提交。
- **D4｜门按规范顺序跑，不得重排（rev2 修 P2-15）**：`publish-ops.md` §2 规定
  **parity → derive-sync-set --report + version → version-sweep → migration → supporting checks**，
  并明写「Do not parallelize, defer, or reorder these gates; stop at the first blocker」。
  supporting checks 含 `pack-registry-driftcheck.sh`（advisory）与——因本单**改动 `tad.sh`**——
  **强制**的 `bash tad.sh --verify-denylist` 必须 exit 0 才能 tag（§2.5，rev1 完全漏了，P1-5）。
  当前实测：parity **0**、migration **0**、version **1（29 stale）**、version-sweep **1（12 个 Layer 1
  stale + 478 个 Layer 2 advisory）**。后两个 exit 1 是**预期**——它们在说"还没 bump"。
- **D5｜发布序列三条分离命令**（`publish-ops.md` §4 逐字），三条命令的目标 commit 统一为
  **记录的 tip**（rev5：不再写死 commit B），每条之前重读前置并 CAS 其命名 action。
  分离是技术安全边界，不是三次人工审批。**tag 消息文本在此固定**（rev2 补，reviewer 收尾）：
  `v2.41.0 — Lite authority model v2 (contract mandate replaces per-command approval) + Layer 1 AC-driven self-check`

  `claude_md_strategy: "overwrite"`**，误跑 sync 会覆盖下游自有的 `CLAUDE.md` 而 rev1 的 AC11 报 PASS。

## AC

**约定**：命令从物理根执行（`git -C "$repo_root"`）。`verify.sh` 禁进程替换 `<(...)`（集合运算走
`mktemp`）；定长匹配一律 `grep -F … -e "$PAT"` 并**显式判 exit code**（`rc=$?`），不得用裸 `||`/`&&`
（依据 `patterns/shell-portability.md` 的 `ugrep Host…Require -e` 与 `grep -F Disables Regex Anchors`
两条）。`ruby` / `shasum` / `find` / `xargs` 为系统自带豁免工具，用途分别限于 YAML 解析、内容摘要、
清单派生。
**`find` 的复合条件必须加括号**（rev4 新增，与上面两条并列为脚本级约定）：凡表达式含 `-o` 且带显式
action（`-print0` 等），必须写成 `\( cond1 -o cond2 \) -print0`。`find` 在有显式 action 时不补隐式
`-print`，不加括号会让 action 只绑定到最后一个条件——**静默漏掉绝大多数结果而不报错**（见 AC11(b) 的
实测反例）。
