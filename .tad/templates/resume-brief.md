# Resume Brief（换执行者交接件）

> 同一 phase 换执行者（非同会话 resume）时，由交出方（或派发方）填写、接手者开工前读完。无 brief 不开工；brief 缺失时的处置见文末节。

- 原 dispatch_id: [被接手的原派发 id]
- dispatch_history: [该 phase 迄今全部 dispatch_id，逐个全列]
- phase 指针: [Epic 文件路径＋Phase 编号，或 conductor journal 路径＋行指针]
- 交出方: [交出者席位/角色＋dispatch_id]
- 接手方: [接手者席位/角色]
- 日期: [YYYY-MM-DD]

## 输入（缺一不开工）

- 原 dispatch_id 与 dispatch_history：见抬头字段，接手前逐个核对无缺漏。
- 已落产物清单（逐件列全）：

| 路径 | 状态 | 断点（半成品必填） |
|---|---|---|
| [产物路径] | 完成 / 半成品 / 未动 | [半成品停在哪一步、缺什么；完成与未动写 —] |

- 版本状态一行：[产物文件清单＋各件 sha256 或版本面表述]。本仓禁 git 命令，不以 git 状态充版本状态。

## 接手第一动作

1. 照已落产物清单逐件回盘核实：路径在盘、状态属实（半成品的断点与实物相符）。
2. 在 phase 记录（Epic 的 `## Run` 块或 conductor journal）写接手行：接手人、时点、核实结论。
3. 完成 1–2 后才许动手；核实不符先报派发方，不自行补判。

## 禁令

- 不重做已落盘步
- 不改判据
- 不覆写前任文件（修订走新版本名或修订行）

## 上限

同一 phase 换人至多 2 次；第 3 次须走 re-plan、不许再发 brief。

## brief 缺失时

接手者的第一份产出是「brief 缺失」记录＋盘面清单（已落产物逐件实查），记录落 phase 证据面；其后以该清单为临时输入开工，禁令与上限照旧。
