# TAD v4.0.13

Released 2026-11-23.

Patch release. It fixes what 4.0.12 left open for users who upgrade: the installer now shows this release's notes, the three `web-ui-design` files that upgrades kept at their 4.0.11 copies are replaced, and the structural check passes after a fresh install. It also makes the Gate 3 check script fail a bug-fix matter that lacks its before and after evidence. It is built as the 4.0.12 public tree plus an allow-list of framework files from the private source.

## What changed

- **Upgrade release notes.** Every CHANGELOG bullet now starts with a bold lead, which is what the upgrade's "What changed:" block prints; 4.0.12 had none, so upgrades to it printed `no release notes`. A new release gate, `release-verify.sh release-notes <repo_root> <version>`, reads the installer's own pattern from `tad.sh` and blocks a release whose section has no line the installer reads.
- **Pack files left stale by upgrades.** An upgrade now replaces a pack file whose bytes equal any file of any TAD release (matched by content only: its git blob id is listed in `.tad/provenance/framework-released.tsv`, with no path) where the pack meta used to keep it. Files you edited and files you emptied are kept, as before. When the release ledger cannot be read, nothing changes and the installer prints one warning line. This fixes `.agents/skills/web-ui-design/SKILL.md`, `DESIGN-TEMPLATE.md` and `references/brand-tokens.md`, which every upgrade from 4.0.11 kept at their 4.0.11 copies. The cause was the installer's pack merge (a first install records the pack as `migrated`, and later upgrades keep files that differ from the meta), not the pack source.
- **Structural check after a fresh install.** `release-verify.sh structural` accepts `.tad/migrations/genesis.yaml`, the anchor the installer writes at a fresh install, and prints an info line for it; every other extra or missing file still fails.
- **Bug-fix sequence.** One sequence for every bug fix, written once in `.tad/templates/review-contract.md` §10 (BF1–BF5): reproduce first and save the failing output, fix, re-run the same case and save the passing output, and the run reviewer re-runs it. Cora's triage and the `*bug` path point to it.
- **Bug evidence checked.** `gate3-check.sh` now decides whether a matter is a bug fix and fails it when the run verdict's `## Bug evidence` lacks a passing before and after row. Reruns may be `not-run` with a reason; those go to Gate 4. For a handoff, the marks are a `## Reproduction` section (the `*bug` path), a `- **Bug fix**:` line in the Epic's `## Requirement`, or a `bug_repro:` line in the completion report. On the simple tier, the run reviewer gives the script the task's address, `conductor-simple-<date>.md:<n>` (the journal file and the line number of the task's `request:` line, as Cora names it in the dispatch); the script reads that one line, does not look for an AC table, and treats the task as a bug fix when that line has a `bug_fix:` field or the completion report has a `bug_repro:` line. A journal given without `:<n>`, or a line that is not a `request:` line, fails. Handoff and Epic matters without a mark print and exit exactly as before; a simple task without a mark prints one `SIMPLE task` line and exits 0.
## What this release holds back

- As at 4.0.12: working notes and process records (`docs/pm/`, `.tad/active/` and the other project-owned directories) keep the copies the public repo already has; the CI workflow file `ci/tad-tests.yml` and the review benchmark record stay held.

## Corrections to the 4.0.12 note

The 4.0.12 note is not edited; these are its corrections.

1. **The download install ran and passed.** The 4.0.12 note said the download install was pending. It ran on 2026-11-17 after the push and the tag (the 4.0.12 release record, item B3): a fresh install with the README command into an empty project exited 0 at version 4.0.12, and the tag's GitHub archive held version 4.0.12.
2. **The questions "asked at the release stop" were answered.** The freshness gate was waived by the maintainer (no date edited), the private-content lines were published as they are, the held files were kept held, and the step3f transcripts were carried from the previous cycle.
3. **Upgrading needs no `--platform`.** The 4.0.12 "Upgrading" line showed `--platform codex`; the README command and `bash tad.sh --source <dir>` work without it.
4. **The web-ui-design gap hit every upgrade from 4.0.11, the README command included.** 4.0.13 fixes it (see "Pack files left stale by upgrades"); the cause was the installer's pack merge, not the pack source.

## Upgrading

The README command:

```
curl -sSL https://raw.githubusercontent.com/Sheldon-92/TAD/main/tad.sh | bash -s -- --yes
```

or, from a downloaded release folder, `bash tad.sh --source <dir>`.
