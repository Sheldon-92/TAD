# TAD v4.0.2

Patch. Cora now triages every request before acting, the installer stops nesting a skill inside itself on GNU `cp`, and the source repo loads its own roles in Claude Code.

## What changed

- Cora states the tier (simple, handoff or Epic), the plan and the estimate before acting, and the human's yes is the go-ahead. New section "When an instruction meets a rule": she names the rule an instruction would break and offers the way that keeps it. Epics carry a `**Budget**:` line, and fix-review loops continue while reviews converge instead of stopping at a fixed round count.
- Installer: skills are copied by contents (`cp -R "dir/." "target/"`), so an existing skill directory is merged in place on BSD and GNU `cp`. A `.agents/skills/<name>/<name>` copy left by an older installer is repaired on the next install, and the post-install check reports one that remains.
- Source repo only: `.claude/skills/<name>` symlinks to `.agents/skills/<name>`, so `/cora`, `/alex` and `/blake` load in Claude Code when working on TAD itself.

## Upgrading

Re-run the installer for your harness (`--platform claude-code|codex|opencode|cursor`). There are no file deletes or renames; `4.0.1-to-4.0.2.yaml` is an empty hop.

## Known limits

- GNU `cp` behaviour was tested through a PATH shim, not on a real GNU host.
- Cora's reliability measurement phases were cut by the human; the protocol change was gated and reviewed but not re-measured on a fresh session.
- The download install and upgrade paths (curl, `npx github:`, `tad-update`) were not exercised for the changed installer (`tad.sh`, `portable-extract.sh`), and no `git archive` upgrade from the 4.0.1 tag was run.
