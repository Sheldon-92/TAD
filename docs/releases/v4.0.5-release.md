# TAD v4.0.5

Patch. Installer fixes only, found when a project was upgraded from 4.0.3 to 4.0.4. Nothing changes in how Cora, Alex, Blake or the gates work.

## What changed

- Post-install check: after an install or update the installer reports every skill entry under `.claude/skills/` and `.agents/skills/` that does not resolve to a `SKILL.md` (broken link, not a directory, no `SKILL.md`). It reports only; it never fails the run.
- Backups: the in-project backup folder names the real `<from>-to-<to>` versions (it used to say `4.0.3-to-4.0.3`), and each backup has `changes.tsv` listing every file added, changed or removed by the run.
- Retention: repeated same-version `--force` runs no longer delete the last backup taken before a version change (newest 2 plus the newest differing-version one, at most 3 kept).
- Non-ASCII project names: the home backup directory is `<readable name>-<path hash>` instead of underscores.
- Rulings file: three protocol lines now say `human-rulings.md` is read "if it exists"; the installer does not create it. A dangling Epic path in `principles.md` is repointed.

## Upgrading

Update with `bash tad.sh --platform claude-code` (or `codex|opencode|cursor`) or use `--source`. `4.0.4-to-4.0.5.yaml` removes and renames nothing. Older backups keep their old folder names.

## Known limits

- The full test suite was not re-run on a machine with free disk; the new fixture cases and real-run checks on one throwaway project passed. Linux was not run.
- Release rule: the `git archive` shape of the release commit was installed end to end into one throwaway project before the tag (record: `.tad/evidence/simple/2026-10-20-release-405-completion.md`, local). One real download install from GitHub right after the tag is still open at release time.
