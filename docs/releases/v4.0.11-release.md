# TAD v4.0.11

Installer diagnostics patch. When the installer fails to write a file it now says which file, which step and what the system said, and after a rollback it prints one conclusion about the project: its state, whether anyone has to act, and from which path.

## What changed

- **Failed writes are named.** Each write point listed here (copy, verify, swap, directory creation, symlink stage and swap, pack metadata, `.codex/hooks.json`, version stamp check) prints one line before the rollback starts: `INSTALL-WRITE-FAILED step=<step> file=<path> reason=<system text>`. Multi-line system text is joined with ` | ` and nothing is cut. Any other exit (a bare `set -e` failure, a signal, or a write that is not in that list, such as a bare `mkdir -p`) prints `INSTALL-EXIT step=<last step> status=<n or signal> last-command=<source text> reason=not captured`, and names no file.
- **A stage that failed verification or the swap is kept** inside the rollback snapshot (temp, not reboot-safe), and the log's last statement about it (`KEPT-STAGE:`) is true. If keeping fails the log says so and that the bytes are gone.
- **The rollback prints a conclusion** from what it measured: `PROJECT-STATE: intact | intact-with-exceptions | not-intact`, `ACTION-NEEDED`, `RECOVER-FROM`. Recovery copies that existed before the run (`.tad-backup`, `.tad-migrate-backup.*`) no longer turn a fully restored project into `partial`. Snapshot-entry failures count in `failed=`. `MANUAL-RECOVERY` prints only when action is needed. A read-only audit after the restore names files that differ from their pre-run bytes (for example `.codex/hooks.json`, see the open ticket below) with the path that holds the bytes.
- **A rollback whose snapshot never completed deletes nothing** and says nothing was verified.
- The `aw.*` installer cases no longer pin a version and are real upgrades; they and the new `fn.*`/`rp.*` cases run by name in `run-all.sh`.

## Behaviour to know

- While the installer runs, SIGINT, SIGTERM and SIGHUP are handled: the shell acts on a signal only after the foreground command it is waiting for returns, so a hung write delays `kill` (use `kill -9`). Once the rollback starts, further INT/TERM/HUP are ignored until it ends.

## Not found yet

- **The cause of the 4.0.10 failures in two downstream repos is still unknown.** This release makes the next failure say what failed; it does not fix a cause. The failure happened on a VM overlayfs and was not reproduced on a Mac (RP3 not run).
- Open tickets, not done here: `TICKET-20261102-migrate-rescue-atomicity`, `TICKET-20261102-hooks-json-rollback-gap` (the audit now names the gap; it does not close it).

## Tests that were already red on 4.0.10: fixed in the tests, not in the installer

The full regression was red before this release (a public clone with this tree overlaid). By ruling ("这次一起修") the release also fixes the tests; none of these fixes changes what the installer does to a user's files.

- `check-path-refs`: 18 dangling references, all in historical planning records, a user-local override file named as optional, a gitignored session-state file named in a script and a template, and a recorded fixture corpus. Each is now an allow-list row with its reason (14 rows cover 17 references; the 18th, in a ticket that moved to `.tad/archive/tickets/`, which the check skips, needs no row); two allow-list rows for a file that does exist were removed.
- `installer-data-safety-fixture` `ac2.8`: the case installed a 3.1.0 target under a 4.x source, which the installer correctly routes to the migrate path (it keeps a `.tad-migrate-backup.<ts>`), so the plain-upgrade check saw it as drift. The target is now `<source major>.0.0`.
- `installer-data-safety-fixture` `--case all` ended silently after `fx.c`: `fx.c` read three lines by hard-coded line number, the numbers had moved, and a zero count ended the script under `set -e`. It now finds the lines by content.
- `installer-data-safety-fixture:fx.k`: `claude-adopt/` (the archive of a legacy Claude Code install, made by the upgrade in that case) is a legitimate name next to the backups; the check did not know it. The failure message now lists the offending names.
- `backup-lifecycle-fixture:caps`: the case expected one named seed directory to survive retention, but the real upgrade adds hop directories of its own, so which seed survives depends on the release. It now checks the rule itself: the two newest target versions present are kept.
- `tad-update-fixture:post-update`: the "old lead" section of the fixture changelog was stamped with the previous release's version, which falls inside the range the project is upgraded across (4.0.5 to now), so it counted as a lead. It is now stamped 4.0.5.
- `tad-update-fixture:release-gates` is a release-time check: gate 2 (version) lists every mention of the previous version still in the tree, gate 4 (migration) reads `git describe` of HEAD^, so the version bump must already be committed on top of the previous tag, and gate 7 (provenance) needs the ledger regenerated after that commit. `run-all.sh` now names it as excluded with that reason and runs it only with `TAD_TEST_RELEASE=1`, in the release dispatch. It cannot pass before the bump is committed and the ledger regenerated, which only exists at release time. Gate 2 also used to demand that version exit 0, which a patch release with history mentions of the old version never does; it now accepts exit 1 on a patch bump when the triage record `.tad/evidence/releases/<version>-version-triage.md` exists, as the release protocol already does. On the 4.0.11 release tree it passes.

## Running the tests

`bash .tad/tests/run-all.sh --quick` runs the default entries plus ten installer cases that cover the write, failure-naming and rollback paths, `tad-update-fixture:states` and the backup retention case: about 20 minutes on a Mac under load. `TAD_TEST_FULL=1` is the full run (several hours); every entry now prints `TIME <name> <seconds>s`.

What has and has not run, stated plainly:

- No full run has ended `RUN-ALL: PASS`. The one full run ended `RUN-ALL: FAIL` on three entries (`tad-update-fixture:archive-shape`, `multi-platform`, `first-hop`); they build their candidate with `git archive HEAD`, so they need a committed tree, and each passed on a committed clone.
- Three stale tests stay excluded and are named by `run-all.sh`: `gate-exercise` (its temporary repo has no hop manifest), `yolo-recovery.test` (a fixed commit range that keeps growing) and `yolo-round.test` (a hash recorded by a past run that the driver no longer matches). Their other cases pass.
- `release-gates` runs only at release time (above).
- The full mode runs once on the release tree, committed, before the tag. The RP3 bind and Linux were not run.

## Upgrading

`bash tad.sh --platform codex` (or `claude-code|opencode|cursor`, or a comma list), or `--source`.
