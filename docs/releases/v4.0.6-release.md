# TAD v4.0.6

Patch. Cora and the design loop, fixed from real use in three projects. The installer is unchanged.

## What changed

- Design loop: look first, design steps ask for decisions not code, no rule-on-rule fixes, and a convergence stop that ends a patch chain in a re-plan.
- Clarification: Cora checks the block-by-block playback before you confirm it.
- Dispatch count: `cora-check.sh dispatches` counts from files on disk, not from Cora's tally.
- Why not me: Cora says why a task is not hers or a subagent's before it asks you to do it.
- Gate 4: one report shape across all copies, checked by `cora-check.sh gate4-record`.
- Resume: Cora resumes an Epic from disk.

## Upgrading

Update with `bash tad.sh --platform claude-code` (or `codex|opencode|cursor`) or use `--source`. `4.0.5-to-4.0.6.yaml` removes and renames nothing.

## Known gaps

Five open P1s carried from the Epic's gate reports (`.tad/evidence/yolo/cora-loop-fixes/EPIC-COMPLETION.md`):

- Look-first has no path when a subagent cannot see your browser.
- Some P0 classes rest on reviewer judgment; one local defect forces a re-plan.
- `cora-check.sh dispatches` exits 2 on Epics with no `estimate <N>` in the Budget.
- `gate4-record` and the playback check accept filler content; the disk count is a floor when files are overwritten.
- `AGENTS.md` "How a piece of work goes" still orders tier after playback; release-check rows cannot pass in a clone.
- On macOS with Homebrew bash 5.3.x first on PATH, the installer can occasionally exit 139 (a crash inside that bash's locale reset, not in TAD). Nothing is half-installed. Run the same command again, or use `/bin/bash tad.sh` (or pipe to `/bin/bash -s --` instead of `bash -s --`).

The first live Cora run on a downstream project is the real test of these rules. Release rule: the `git archive` shape of the release commit is installed into one throwaway project before the tag (record: `.tad/evidence/simple/2026-10-21-release-406-completion.md`, local).
