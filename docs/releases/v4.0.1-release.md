# TAD v4.0.1

Patch. Upgrading a 3.x project to 4.0.0 left three old Alex protocol files beside Cora's: `yolo-manual-conductor-protocol.md`, `update-roadmap-protocol.md` and `status-panoramic-protocol.md` (under `.agents/skills/alex/references/`). 4.0.1 removes them.

## What changed

- The cleanup now runs through `.tad/deprecation.yaml` (key `"3.0.0"`), which works on download installs. The 4.0.0 migration manifest was rejected by the migration engine, and even a valid one does not delete on a download install (the engine needs git history of the source). The manifest is valid now and the status protocol is a delete, not a rename onto Cora's file.
- The release gate `migration` now runs the engine's validator over every manifest from the previous major on.
- The 4.0.0 upgrade notes are corrected.

## Upgrading

Re-run the installer for your harness (`--platform claude-code|codex|opencode|cursor`). Projects on 3.x and projects already on 4.0.0 both lose the three files. A customised copy is removed too; a copy is kept under `.tad-backup/`. Nothing under `.claude/`, `CLAUDE.md` or `.codex/hooks.json` is touched. `.tad/project-knowledge/` is untouched (hash checked).

## What was run

Five real upgrades from `git archive` installs (3.3.0 on Codex and Claude Code, 3.2.0, 3.0.0, and 3.3.0 via 4.0.0) to a `git archive` of this release tree, in scratch directories: all exit 0, 0 stale files afterwards. The 4.0.0 step reproduces the bug (3 stale files). Records are under `.tad/evidence/`, which is not shipped.

## Known limits

- The engine's delete and rename never run on a download install; `deprecation.yaml` is the only cleanup path there.
- 2.x projects are not cleaned (key `"3.0.0"` is a floor).
- A 3.0.0 project gets an engine chain-gap warning (no `3.0.0-to-3.0.1` hop); installation still succeeds and the cleanup runs.
- `2.42.0-to-2.43.0.yaml` fails engine validation (2.x only).
- Not run: a real `curl | bash` upgrade from published `main`, interactive Claude Code, OpenCode and Cursor upgrades.
